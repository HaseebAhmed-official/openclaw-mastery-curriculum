# Product / Operator Track

## Role

Own safe, useful application of an existing harness or agent product without treating configuration as trivial or outsourcing trust to the vendor.

## Outcomes

- turn user work into measurable requirements and a deterministic baseline
- select workflow/agent patterns and bound tools, data, authority, and escalation
- configure context, memory, policy, approvals, and human handoff
- evaluate realistic task outcomes, failures, overrides, latency, and cost
- write operating, accessibility, privacy, incident, and change guidance
- audit current product behavior from primary evidence

## Required Evidence

- LAB-C6, LAB-C7, LAB-C8, LAB-D2
- evaluated workflow or assistant with at least one denied/failed path
- user and operator journey with intervention points
- data/authority map and operating policy
- current product claim ledger
- delayed changed-user or changed-tool task

## Advanced Topics

Adoption experiments, human-computer interaction, conversation/work design, content provenance, model/provider routing, feedback systems, safe automation, and organizational change.

## Capstone Emphasis

Demonstrate that the system improves a real task under bounded authority. Measure human correction and override, not only task completion. A polished demo without independent user/task evidence fails.
