## Scope Rule

Focus on curriculum, learning, assessment, source validation, and portfolio evidence. Do not spend effort installing or running OpenClaw unless the user explicitly asks.

## Workflow

1. Identify the learner's current OpenClaw target: beginner, operator, DevOps, security, plugin developer, contributor, local models, or teacher.
2. Map the target to existing curriculum files and labs.
3. Use the mastery ladder to define current and target level.
4. Assign a session from the curriculum with retrieval checks and a hands-on artifact.
5. Add release-aware source checks when content depends on current OpenClaw behavior.
6. Review produced work against curriculum rubrics.
7. Propose state and portfolio updates.

## Output Contract

Return:

- current OpenClaw learning position
- next curriculum unit
- required reading
- practice task
- assessment task
- portfolio artifact
- source/release check
- proposed state update
